# DVA v0.4.5

이 문서는 **미공개 v0.4.5 후보**의 릴리스 노트입니다. 공개 설치 버전은 아직 v0.4.4입니다.
개발 환경의 준비 실패·취소 전달과 설정 진단을 보완하며, `modes`·`default_mode`·`--mode`는
이번 후보에서 제거하지 않습니다. 제거는 승인된 v0.5.0 범위입니다.

## 업그레이드 주의사항

- `up`·`restart`의 readiness timeout, 준비 중 native PID 종료, 호출자 취소는 경고 후 성공으로
  끝나지 않고 비0으로 종료합니다. 자동화는 실제 준비 실패를 처리해야 합니다.
- `up`·`restart`·`stop`·`status`가 호출자와 SIGINT·SIGTERM·SIGHUP 취소를 전달합니다.
  취소 전 수행한 작업이나 조회 결과는 남을 수 있고 이후 작업은 중단됩니다. 취소는 전체
  원상 복구를 뜻하지 않습니다. `down`의 기존 best-effort 정리 정책은 유지합니다.
- `status`는 취소 시 수집한 부분 결과를 보존하고 실패로 종료합니다. text/JSON 소비자는
  출력이 존재해도 종료 코드를 확인해야 합니다. 일반 조회 오류의 기존 처리는 유지합니다.
- 새 진단으로 기존 설정의 `validate --strict`가 실패할 수 있습니다. 특히 subproject의
  설정 파일 누락과 과도한 ignore 범위를 확인하세요. `doctor --strict`는 `sops_source`를 선언한
  env target이 없으면 실패합니다. 일반 경고가 곧 모든 실행을 막는 입력 오류라는 뜻은 아닙니다.
- `make install` 기본 대상은 `~/.local/share/ce/bin` 한 곳입니다. 이전 `~/.local/bin/dva`나
  Go bin 사본은 자동 제거하지 않습니다. 설치 경고와 실제 PATH 사본을 확인하세요.
- `ci.profiles.<name>.fail_fast: false`를 선택하면 독립적인 준비 완료 step은 첫 실패 뒤에도
  실행합니다. 실패한 의존 step은 건너뛰고 전체 profile은 실패합니다. 기본 fail-fast는 유지하며,
  취소·profile timeout·checkpoint 무결성 오류는 계속 실행하는 대상이 아닙니다.

## 설정과 안정성 개선

- `intentional_shadow: true`로 의도적인 root interaction/subproject 경로 가림을 선언할 수 있습니다.
- `suggestion_ignore`는 기존 문자열 외에 reason·`max_matches` 객체형 규칙을 받습니다.
  객체형 glob은 cap이 필요하며 cap 초과는 strict 실패입니다.
- `suggestion_aliases.makefile`은 root interaction과 문서화된 Makefile target의 검증용 연결입니다.
  새로운 실행 alias를 만들지는 않습니다.
- 잘못된 stack Compose profiles에는 plan entry의 수정 위치를 안내하며, 부모가 명시적으로 소유한
  Compose 파일을 child의 미등록 drift로 오보고하지 않습니다.
- strict 판정은 글리프 대신 선언된 심각도를 사용하고, 스킬 번들 해시는 호출별로 격리합니다.
  설치된 DVA가 없는 환경에서의 자체 CI 복구 검사도 보완했습니다.

## 알려진 제약

TASK-575의 다음 항목은 재현됐으며 이번 후보에서 수정되지 않았습니다.
조사 근거는 [env 경고 재현 기록](../docs/env-warning-reproduction.md)에 있습니다.

- root `doctor`만으로 child의 암호화 env target 누락을 모두 확인할 수 없습니다.
  필요한 child 디렉터리에서 진단하세요. `restart`는 누락 target의 unseal 경고를 출력하지 않습니다.
  env 입력 로드 오류를 거부하는 기존 정책은 별개로 유지됩니다.
- unknown plan의 `up`은 인자 거부 전에 누락 target 경고를 출력할 수 있습니다.
- **보간 경로를 쓰는 encrypted env target은 loader와 env bridge가 같은 파일을 사용하지 않을 수
  있습니다.** fixture에서 loader는 `.env.stg`를 읽었지만, 보간 선언을 그대로 선택한 unseal은
  literal `.env.${T575}`를 생성했습니다. 이 경로에는 복구 hint를 그대로 실행하지 말고,
  encrypted `env_file.path`를 의도한 고정 상대 경로로 명시한 뒤 검토하세요. hint의 shell 인용도
  해결되지 않았습니다. 이 제약의 문서화는 TASK-575의 수락·완료 판정이 아닙니다.

현재 플랫폼·외부 연동 제한은 [지원표](../USAGE.md#버전과-지원-범위)를 따릅니다.
특히 Windows의 local background process·CI·tunnel 실행, 실제 Access 애플리케이션 터널 검증,
Skaffold의 실제 cluster 상태 조회는 archive 제공만으로 지원이 추가되지 않습니다.
