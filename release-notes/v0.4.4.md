# DVA v0.4.4

v0.4.4는 v0.4.3에서 알려진 제약으로 남겼던 `env_file` 경로 문제를 고치는 패치입니다. 지금까지
검증을 통과하던 경로가 오류로 바뀔 수 있습니다. v0.4.3의 validate는 이 경우를 잡지 못하므로,
v0.4.4 바이너리로 `dva validate --strict`를 먼저 실행한 뒤 다른 명령을 쓰세요.

## 호환성 변경

아래 `env_file` 경로는 이제 `required`와 관계없이 `unresolved_path` 오류입니다. 실행·정리·관찰
명령과 `dva provision`(`--dry-run` 포함)이 멈추고, `dva validate`가 파일을 열지 않고 미리 경고합니다.

- 지원하지 않는 문법 `${A:?x}`, `${A:+x}`: 경로에서 빼고 기본값이나 정의된 변수를 쓰세요.
- 변수 값에 든 `${`: 해당 값을 실제 경로로 바꾸세요.
- `.`, `/`로 확장되는 경로: 파일을 가리키도록 고치세요.
- 맨 앞 변수가 비어 절대 경로가 되는 `${E}/.env`, `${PREFIX}/etc/app/.env`: 절대 경로를 직접
  적거나 `${PREFIX:-/}/etc/app/.env`처럼 기본값을 지정하세요.

## 알려진 제약

- `vars`나 `environment:`에서 이미 펼쳐진 값은 빈 변수 판정이 잡지 못합니다.
- `$${S}/.env`처럼 `$` 바로 뒤에 값이 있는 참조가 오면 없는 `$x`를 원인으로 표시하며 거부합니다.
- 값이 `$NAME` 형태로 남는 경로는 `unresolved_path`로 잡히지 않아 validate를 통과합니다. 그 이름의
  파일이 없으면 `required: true`는 `missing_required`로 실패하고 `required: false`는 건너뜁니다.
- `..`처럼 존재하는 다른 디렉터리로 확장되는 경로는 validate를 통과한 뒤 열 때 `inaccessible`로 실패합니다.
