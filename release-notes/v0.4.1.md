# DVA v0.4.1

v0.4.1은 v0.3.0 다음의 첫 공개 릴리스입니다. v0.4.0 tag는 GitHub Release와 배포 산출물
없이 남았으므로, v0.3.0에서 올라오는 사용자에게는 이 릴리스가 0.4.0 섹션의 변경까지
함께 전달합니다.

## 개발 환경과 입력

- `dva config env reseal`이 선언된 `sops_source`를 같은 경로에 재암호화합니다.
  평문 target은 읽거나 쓰지 않고, 실패해도 기존 암호화 source를 보존합니다.
- `dva secret push`가 `provider: kubernetes` 목적지에 선언한 키만 server-side apply(field
  manager `dva`)로 적용하고, `dva secret status`가 키 이름만 대조합니다. null 값·잘못된
  Secret 이름은 전송 전에 거부하고, 선언한 kubeconfig와 context만 사용합니다. 같은 Secret의
  다른 키를 client-side `kubectl apply`로 쓴 적이 있으면 그 키는 지워질 수 있으므로
  [전송 계약](https://github.com/ScriptonBasestar/dva/blob/v0.4.1/docs/69-kubernetes-secret-target.md)을 확인합니다.
  `dva config validate`도 kubernetes 목적지 선언을 검사합니다.
- `dva init`이 sops 암호화 후보를 감지하면 `env_file`의 `sops_source`를 함께 선언하고,
  선언이 없으면 `dva doctor`가 선언 예시를 안내합니다.
- kubectl·helm entry는 Cloudflare Access tunnel을 선언할 수 있습니다. DVA가 시작한
  프로세스만 종료하며 JWT는 출력하지 않습니다. 이 릴리스에서 실제 Cloudflare Access
  애플리케이션을 통한 터널 개통·종료는 검증하지 않았습니다. 만료된 Access 토큰은 미인증으로
  판정합니다.

## 실행과 진단

- `dva doctor`의 project command는 설정 디렉터리에서 실행되며 종료 코드·timeout·실행
  근거를 구분해 보고합니다. 신호로 종료된 command는 `command terminated by SIGTERM`처럼
  실제 신호 이름으로 보고합니다.
- `ci.profiles.<name>.tool_jobs`로 Rust build 단계의 tool worker 수를 명시할 수 있고,
  생략 시에는 논리 CPU와 단계 병렬도에서 안전한 기본값을 계산합니다.
- `dva ci --subproject <name>`이 root의 CI 프로필을 실행하면서 root가 선언한 subproject
  이름을 `DVA_CI_SUBPROJECT`로 단계에 넘기고 receipt에 기록합니다.
- CI receipt가 Git 입력 attestation의 측정 commit(`attestation.commit`)과 dirty 여부를
  기록합니다. 상위 저장소의 ignored 경로 아래 root는 commit을 기록하지 않습니다. Git 입력을
  하나도 읽지 못한 root는 `available: false`와 이유를 남깁니다.
- Make include와 `suggestion_ignore`의 구성 발견 진단을 보완했습니다. 이미 interaction에
  가려진 ignore는 warning으로만 보고하며 validation 실패를 만들지 않습니다.

## 수정

- 손상된 pidfile이 1이나 DVA 자신의 프로세스 그룹을 가리키면 `down`/`stop`/`status`가
  다른 프로세스에 신호를 보내지 않고 pidfile 경로와 함께 오류로 멈춥니다.
- composition child에서 DVA health check가 없는 compose entry도 Compose `--wait`를
  유지합니다.
- 번들 `dva` 스킬이 `dva build`를 `dva run build`의 생략형으로 설명하던 오류를 고쳤습니다.

## 릴리스 절차

- 공개 Release는 사람이 먼저 push한 tag에만 만들어집니다. GoReleaser가 tag를 만들지
  않으므로 release token은 Contents 권한만 가집니다. 저장소 운영자를 위한 변경이며 설치와
  사용에는 영향이 없습니다.

## 호환성

- v0.3.0에는 이 릴리스의 새 선언·진단 계약이 없습니다. 업그레이드 전
  `dva config validate`와 `dva manifest -f json`으로 현재 프로젝트의 선언과 명령을
  확인합니다.
- source-only였던 `task-queue-start` 연동은 제품 범위에서 제거됐고 그 이름은 더 이상
  예약하지 않습니다. 기존 공개 built-in `ci`, `secret`, `job`은 계속 예약어입니다.
- `dva down <plan> --purge`는 계속 파괴적 동작입니다. 자동화에 넣기 전에 선택한
  plan·서비스와 cleanup 범위를 확인합니다.

이 노트는 주요 변경과 업그레이드 주의사항만 요약합니다. 전체 변경·호환성 항목은
[CHANGELOG](https://github.com/ScriptonBasestar/dva/blob/v0.4.1/CHANGELOG.md)의 0.4.1과
0.4.0 섹션을 따릅니다.
