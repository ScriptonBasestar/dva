# DVA v0.4.3

v0.4.3은 `env_file` 경로 변수 확장, 더 엄격한 설정 검증, CI의 유한 OCI 단계와 독립 root child
CI를 담은 릴리스입니다. 호환성 변경이 있으니 업그레이드 전에 `dva validate --strict`를
실행하세요.

## 호환성 변경

- `env_file` 경로의 `${VAR}`, `${VAR:-default}`를 `vars`, `environment:`, OS 환경 변수로
  확장합니다. 해석되지 않는 참조는 `required`와 무관하게 오류입니다.
- plan이 소유자가 선언하지 않은 environment를 가리키면 `dva validate`가 실패합니다.
- 알 수 없는 interaction `runner:`를 거부합니다. 조용히 compose로 실행되던
  `runner: native`도 이제 거부됩니다.
- `dva skill install`은 더 새로운 릴리스가 설치한 스킬을 `--allow-downgrade` 없이 교체하지
  않습니다.

## 추가

- 유한 OCI CI 단계: `run` 대신 `oci`로 digest 고정 로컬 Docker image에서 실행합니다.
  [OCI 단계](../docs/ci-oci-steps.md)를 참고하세요.
- native step의 `child_ci: independent-root`. Manifest schema가 optional 필드를 더해
  1.10이 됩니다.
- `dva status --all`로 `default_plan`과 무관하게 전체 stack을 조회합니다.

## 수정

- `dva down <plan>`, `dva stop <plan>`이 plan의 compose profile을 넘깁니다.
- plan 경로의 `dva status --json`이 JSON을 출력합니다.
- 나머지 변경은 CHANGELOG의 0.4.3 섹션을 참고하세요.

## 제거 예정

- `modes`/`default_mode`는 v0.5.0부터 스키마가 거부합니다. `dva config migrate`로 이관하세요.

## 알려진 제약

- 이 버전에서는 `${A:?x}`, `${A:+x}` 같은 미지원 문법의 `env_file` 경로가 검증을 통과해 문자
  그대로 열립니다. 경로 전체가 빈 값으로 확장되면 config 디렉터리를 열어 읽기 오류가 납니다.
  다음 패치에서 둘 다 `unresolved_path` 오류가 됩니다.
