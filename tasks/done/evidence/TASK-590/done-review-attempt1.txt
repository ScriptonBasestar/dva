   Cause (inferred from stack): captureStderr (internal/cli/plan_scoped_hooks_test.go:334-352) reads the pipe only
   after fn returns, so once the stderr output exceeds the pipe buffer the writer blocks forever
   (orchestrator.go:139 Fprintf blocked). Why this environment produces that much stderr is not established.
   Lead only: SOPS_AGE_KEY_FILE is set in this shell, and the test exercises sops_source warnings. Not verified.
   This should go to findings, separate from TASK-590.
F2 (non-blocking): the "dirty" check uses `git status --porcelain`, which omits ignored files, and non-force
   `git worktree remove` deletes ignored files. Ignored content inside a snapshot (for example a local .env or
   provisioned dependencies) is removed without a refusal. This is consistent with git's own definition of a
   clean worktree, but neither the card nor the RemoveSnapshot doc spells it out. TASK-591 should decide whether
   to surface it.
F3 (non-blocking): Check does not flag a snapshot that is no longer detached (someone ran `git switch` inside it)
   when HEAD still equals the recorded commit. EnsureSnapshot's reuse path does check Detached. Minor asymmetry.
