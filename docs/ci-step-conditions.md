# CI native 단계의 조건부 선택

## 책임과 범위

프로젝트는 어떤 검사가 필요한지 판단하고 DVA는 선언된 단계의 실행·재사용·결과를
소유한다. `condition`은 native `run` 단계의 읽기 전용 선택 명령이다. OCI와
`child_ci`에는 사용할 수 없다. 같은 root에서 DVA를 중첩 실행하거나 프로젝트별
영향 범위 규칙을 DVA에 복제하지 않는다.

```yaml
version: "0.5.2"
ci:
  profiles:
    dev:
      timeout: 5m
      steps:
        - name: selected-unit
          run: make unit-test
          timeout: 2m
          condition:
            run: ./tools/select-unit --json
            timeout: 10s
```

예시 명령은 프로젝트가 제공한다. 정상 종료한 명령이 stdout에 정확히
`{"selected":true}` 또는 `{"selected":false}`를 출력해야 한다. 키 누락·중복·추가,
불리언이 아닌 값, 뒤따르는 JSON이나 4096바이트 초과 출력은 실패다. nonzero 종료·취소·시간
초과도 실패이며 생략으로 바꾸지 않는다. stdout과 stderr 원문은 로그에 남기지 않는다.

## 실행 순서와 결과

선행 의존성 성공 → 조건 평가 → 성공 결과 조회 또는 검사 본체 실행 순서다.
조건은 단계와 같은 환경·작업 디렉터리를 사용하며 양의 유한 timeout을 명시한다.
단계·프로필의 남은 기한보다 오래 실행할 수 없다. 기존 process group 감독과 정리를
사용하며, 조건 명령도 외부 상태를 변경하지 않도록 프로젝트가 책임진다.

- `true`: 기존 검사 실행·재사용 경로를 사용한다. fresh도 조건은 평가한다.
- `false`: 해당 단계는 `skipped`이며 성공·본체 캐시 증거를 만들지 않는다.
  이 단계에 의존하는 단계도 기존 skipped 의존성 규칙에 따라 실행하지 않는다.
- 모든 단계가 skipped면 전체 결과도 `skipped`다. 선택 평가의 정상 종료를 CI PASS나
  테스트 통과로 소비하지 않는다. 일부만 실행된 성공은 선택된 범위의 성공이다.

receipt는 조건 정의의 지문과 판정 결과를 본체 재사용 정보와 구분한다. 조건 명령은
본체에 입력을 전달하거나 산출물을 준비하지 않는다. 따라서 본체 성공 재사용과 별개로
매 실행에서 조건을 먼저 재평가한다. `--lookup`과 dry-run은 조건을 실행하지 않는다.
lookup은 조건 미평가를 표시하고 조건부 본체의 재사용 가능성을 확정하지 않는다.

## 프로젝트 채택

영향 선택기가 이미 검사 본체를 실행한다면, native 단계에 위임한 검사만 기존 직접
실행에서 제외한다. 선택과 실제 검사가 각각 한 번만 실행되는지 확인한다. 계획 오류,
검사 0개, 공유 입력·삭제·symlink 등 전체 확대 조건을 생략 성공으로 바꾸지 않는다.

공통 단계 선언을 다른 프로필에 합칠 때 `depends_on`도 해당 프로필에 맞게 재선언한다.
full의 선행 조건을 dev에 잘못 상속하거나, 생략 가능한 단계 뒤에 필수 검사를 연결하지
않는다. 전체 검사·audit가 필수 검사를 모두 평가해야 한다면 해당 단계에는 조건을
붙이지 않고 그 불변식을 프로젝트 회귀 검사로 유지한다.

조건은 전체 검증·통합·배포 승인을 대신하지 않는다. 재사용 경계는
[CI 결과 재사용](75-ci-result-reuse.md), 실행 감독은 [CI 프로필](53-ci-profiles.md)을 따른다.
