# 개발 수명주기별 CI 검사 계약

이 문서는 이벤트별 검사 설계와 채택 기준이다. 이벤트는 검사 목적을 구분하고,
프로필은 프로젝트가 선언한 검사 묶음을 실행한다. 표는 자동 실행이나 DVA 내장 기능의
존재를 뜻하지 않는다. 실제 런타임은 [CI 프로필](53-ci-profiles.md), 재사용 범위는
[결과 재사용](75-ci-result-reuse.md), 적용 순서는 [채택 계획](ci-lifecycle-adoption.md)을 따른다.
프로젝트의 기존 필수 게이트는 해당 소유자가 수용 계약과 실행 경로를 함께 바꾸기 전까지 유지한다.

## 이벤트와 검사 책임

검사 묶음은 아래 공통 정의를 따른다. `차단`은 프로젝트가 해당 이벤트에 필수 게이트를
채택했을 때 실패·미완료가 막는 행동이다. 일간·주간 결과는 별도로 채택하지 않는 한
merge나 배포의 성공 증거가 아니다. 원격 CI와 일정 실행은 해당 호스팅 시스템이 소유한다.

| 이벤트 | 목적 및 검사 묶음 | 입력 | 실행 위치 | 차단 대상 |
|---|---|---|---|---|
| 편집 중 | 빠른 피드백: 관련 검사 일부 | 현재 작업 내용 | 로컬 | 없음 |
| commit 전 | 커밋 기본 검증: 빠른 검사 | 커밋할 staged 내용과 필요한 의존 입력 | 로컬 | commit |
| 로컬 push 전 | 전송할 변경의 준비 확인: 유효한 증거 또는 필요한 짧은 검사 | 전송할 commit·대상 ref | 로컬 | push |
| 원격 branch push 후 | 브랜치 건전성: 기본 검사 | push된 불변 commit | 원격 runner | 후속 게이트의 증거 여부 |
| fetch / pull 후 | 환경 준비 차이 확인: 설정·의존성 변경을 보고 | 새 source revision·로컬 설정 | 로컬 | 기본적으로 없음 |
| PR/MR 생성·갱신 | 변경 검토: 전체 필수 검사 | 명시된 source commit | 원격 runner | 프로젝트가 정한 merge |
| 병합 직전 | 최신 대상과 결합 검증: 전체 필수 검사 | source·target·결합 결과의 불변 식별자 | 원격 runner 또는 통합 소유자 | merge |
| 병합 후 | 실제 반영된 revision의 건전성: 필요한 smoke·산출물 확인 | 병합된 불변 commit | 원격 runner | 결과 보고; 차단할 후속 행동은 프로젝트 선언 |
| 일간 | 변경 시 생략한 넓은 검사를 보완하고 외부 상태 변화 탐지 | 실행 시 선택한 불변 commit과 외부 조건 | 일정 실행 소유자 | 결과 보고; 별도 선언된 후속 행동 |
| 주간 | 고비용 지원 조합·장시간 검사와 경향 확인 | 실행 시 선택한 불변 commit·측정 조건 | 일정 실행 소유자 | 결과 보고; 별도 선언된 후속 행동 |
| 배포 전 | 배포 후보 적합성: 산출물·설정·호환성 검사 | 산출물 digest·설정·대상 식별자 | 배포 소유자가 정한 검증 환경 | 배포 소유자의 배포 승인 |
| 배포 후 | 실제 대상의 상태 확인: health와 핵심 흐름 | 배포된 산출물·대상 식별자 | 운영 검증 소유자 | 결과 보고; 대응은 운영 소유자 결정 |

`pull`은 Git 동기화다. PR/MR source 검사만으로 대상 브랜치가
포함된 병합 결과를 증명하지 않는다. 병합 판단에는 source SHA, target SHA, 실제로 검사한
결합 결과 SHA 또는 동등한 불변 식별자, 범위, 결과와 실행 환경을 함께 묶어야 한다.
결합 결과가 없거나 대상이 바뀌면 그 증거가 적용되는지 통합 소유자가 다시 판정한다.

스케줄 소유자는 일간·주간의 시간대, 대상 revision 선택, 중복 실행 처리, 누락·실패 알림을
명시한다. 두 스케줄이 겹치면 각 검사에 필요한 범위와 fresh 요구를 비교하여 유효한
증거만 재사용하고, 빠진 범위는 실행한다. 서로 다른 입력·환경의 성공을 합쳐 같은
실행처럼 보고하지 않는다. 미실행 일정은 그대로 보고한다.

## 재사용할 검사 묶음

프로젝트는 목적이 같은 이벤트에 같은 프로필을 연결하고, 범위·자원·실패 시 차단할
행동이 실제로 다를 때만 프로필을 나눈다. 이름은 프로젝트가 소유한다.

| 논리 묶음 | 내용 | 일반적인 이름 |
|---|---|---|
| 빠른 검사 | 변경과 영향 범위의 정적 검사·컴파일·빠른 단위 테스트 | `dev`, `commit` |
| 기본 검사 | 전체 정적 검사·컴파일·단위 테스트 | 프로젝트가 선택한 이름 |
| 전체 필수 검사 | 통합에 필요한 모든 검사와 선언된 통합·E2E 범위 | `full` |
| 전체 fresh | `full`과 정확히 같은 검사 목록을 fresh로 실행 | `audit` |

`audit`은 확대 검사 이름이 아니다. 일간·주간에 `full` 밖의 검사가 필요하면 별도
선택적 프로필이나 외부 작업으로 선언한다. `verify`는 프로젝트가 쓰고 싶을 때만 쓰는
이름의 예이며 DVA 내장 프로필이 아니다. 이름은 검사·권한을 생성하지 않는다.
`audit`의 하위 도구 캐시 우회는 프로젝트 명령이 처리해야 하며 보장 범위는
[fresh 계약](75-ci-result-reuse.md)에 따른다.

프로필 조회는 프로젝트 manifest와 실제 선언을 사용한다. 로컬의 `pre-push`가 이미
완료된 검사의 증거를 사용하려면 소비자가 해당 입력·범위·환경에 유효한지 확인할 수
있어야 한다. HEAD만 같다는 이유로 인정하지 않는다. 현재 DVA의 재사용은 명시적으로
선언한 단계와 동일 canonical checkout 범위다. 별도 실행 없는 유효성 조회나 다른
worktree 간 재사용은 현재 이 문서가 보장하는 기능이 아니다.

## commit 검사와 입력

빠른 commit 검사에는 적용 가능한 다음 항목을 둔다.

- 변경 파일의 포맷 검사와 lint. 검사에서 파일을 자동 수정하지 않는다.
- 영향받는 모듈·소비자의 컴파일 또는 타입 검사와 테스트 코드의 컴파일 확인.
- 관련된 빠르고 결정적인 단위 테스트 실행, 변경된 설정·생성물의 필요한 검사.
- 저장소가 요구하는 커밋 메시지와 무결성 검사. 메시지 hook은 별도일 수 있다.

테스트 코드 컴파일과 테스트 실행은 서로 다른 결과다. 영향 범위는 프로젝트가 신뢰할 수
있는 규칙으로 정하고, 알 수 없으면 필요한 범위를 넓힌다. 전체 race·통합·브라우저 E2E,
다중 플랫폼, 다운로드·의존성 설치는 보통 이 빠른 묶음 밖에서 수행한다. 실제 이동 시에는
기존 수용 계약을 함께 갱신해 필수 검사를 유지한다.

commit 결과는 실제 staged 내용과 필요한 의존 입력에 대응해야 한다. 현재 DVA는 staged
snapshot 격리나 staged 전용 입력 증명을 제공한다고 가정할 수 없다. 프로젝트가 이를
증명하지 못하면 검증 범위와 한계를 보고하고 필요한 게이트를 유지한다. 자동 stash로
사용자의 변경을 옮기지 않는다. 검사가 실행된 작업 트리와 commit 대상이 다르면 동일한
입력의 성공으로 표시하지 않는다.

## 시간·자원·결과

빠른 commit의 초기 설계 목표는 **준비된 warm 실행 30초 이내**, 60초 경고, 2분 제한이다.
이는 미측정 권장 목표이며 현재 모든 프로젝트에 강제되는 DVA 제한이 아니다. 현재 공통
`commit` 계약의 5분 권장·10분 최대와 프로젝트별 선언은
[CI 프로필](53-ci-profiles.md)을 따른다. 제한 변경과 검사 이동은 프로젝트가 측정과
수용 계약 변경을 마친 뒤 적용한다.

프로필 전체, 개별 단계, 지원되는 도구 내부에 유한한 제한을 둔다. 순차 경로와 병렬
임계 경로, 종료·정리 시간을 전체 예산에 반영한다. cold와 warm, 준비·빌드·테스트·자원
대기 시간은 분리해 기록한다. 언어별 숫자는 초기 추정치일 수 있으며 실행 조건과 함께
측정해 조정한다. `max_parallel`, 도구 worker와 공유 자원 `locks`를 함께 설정하고
장비별 자원 값은 로컬 override에 둔다.

timeout은 실패이고 `busy`, 취소, 준비 누락, 실행 중 입력 변경은 통과가 아니다. 원인을
확인하고 조건이 바뀌었을 때 재실행한다. 제한을 임의로 늘리거나 같은 실패를 반복하지
않는다. 통합 검사가 같은 범위를 바로 실행한다면 그 직전 전체 검사를 중복 수행하지
않는다. 성공 보고에는 검사 범위·제외 범위, run ID, 단계별·전체 시간, fresh·재사용
여부와 실행하지 않은 검사를 포함한다.

## 프로젝트 채택 기록

프로젝트는 각 이벤트에 목적, 입력 식별, 검사 범위, 실행 위치, 시간 예산, 차단할 행동,
소유자와 근거의 유효 조건을 기록한다. 적용 상태는 **자동**, **수동**, **미구현**,
**해당 없음** 중 하나와 이유를 남긴다. 미구현이나 해당 없음은 검사 통과가 아니다.
선언된 이벤트가 실제 hook·호스팅 CI·스케줄에 연결됐는지도 확인한다.

DVA는 프로젝트가 선언한 개발 검사를 감독한다. 배포·릴리스·운영 변경과 대상 상태의
실제 조치는 각 소유자의 책임이며 CI 성공은 그 행동의 권한이 아니다. 이 문서의 표는
외부 소유자와의 검증 접점을 설명하며 DVA의 제품 범위를 확장하지 않는다.
