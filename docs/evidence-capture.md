# 선택적 완료 근거 기록

이 문서는 제품 기능이 아니라 에이전트의 작업 완료 절차다. 기본은 비활성이다.
호스트가 별도 목적지의 정책에서 명시적으로 채택한 경우에만 실행한다.
공개 저장소에 비공개 목적지 이름·주소·개인 경로·고객 자료를 적지 않는다.

## 실행 조건

1. 이름이 있는 delivery가 source의 공식 task lifecycle에서 DONE인지 확인한다.
   source repository ID, task ID, execution generation과 전체 source SHA를 확보한다.
2. 호스트의 공식 catalog에서 source ID의 관계를 통해 후보 목적지를 발견한다.
   연결이나 스킬 설치는 쓰기 권한이 아니다. 연결이 없으면 이 선택 단계를 생략한다.
3. 목적지의 AGENTS와 source별 채택 선언을 읽는다. enabled, 범위, 작성자, 실패·중복
   처리와 중단 방법이 명시되지 않았거나 비활성이면 기록하지 않는다.
4. source 읽기와 destination 쓰기 권한을 각각 확인한다. 원본 코드는 복제하지 않고
   고정 commit과 파일 경로로 참조한다. 제한된 자료는 목적지에도 옮기지 않는다.

## 기록과 검증

현재 승인된 작업 에이전트가 CE `tool.project-evidence`의 방법과 목적지 계약을
사용한다. 별도 AI 프로세스·hook·스케줄러·공유 task-state 엔진을 시작하지 않는다.
목적지의 공식 workflow로 분리된 task worktree를 만들고 쓰기 직전 Git root를 확인한다.

task와 execution generation, source SHA 및 완료 receipt를 연결한다. 유의미한 변경
범위로 기존 사례와 중복을 확인한다. 새 SHA나 commit마다 사례를 만들지 않는다.
구현·검증 실행·배포·사용·효과와 사람·AI 기여를 각각 관찰한 범위로만 기록한다.
완료 절차 자체의 변경은 workflow 사례로 설명하며 제품 성능 성과로 세지 않는다.

목적지 계약의 구조·전체 출처 검사와 독립 검토 후 목적지 task를 통합한다.
중간 초안이나 partial 검사만으로 기록 완료를 보고하지 않는다. 보고에는 실제
source 완료와 destination 통합 SHA, 검사 결과 및 남은 한계를 구분한다.

## 실패와 비활성화

탐색·권한·receipt·원본·검사 문제는 기록 단계를 보류하고 원인과 재시도 조건을 보고한다.
source DONE을 취소하거나 제품 작업 실패로 바꾸지 않는다. 목적지의 미완료 작업은
보존하고 같은 변경 범위로 재개한다. 호스트 채택을 비활성화하거나 제거하면 이후
수집을 멈추며 기존 기록을 자동 삭제하지 않는다.

선택 설치 설정은 `.claude/plugins.yaml`이다. 설치는 채택과 별개이며 DVA 자체 제공
스킬을 대체하지 않는다. 이 절차는 에이전트가 수행하는 완료 단계이며 무인 수집이 아니다.
